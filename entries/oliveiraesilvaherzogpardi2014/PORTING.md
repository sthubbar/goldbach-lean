# Provenance of the LeanLab files

`LeanLab/OeSHP2014/` holds the files that the Oliveira e Silva, Herzog and Pardi 2014 entry
needs. AI agents, Claude by Anthropic, wrote all of them in Steve Hubbard's Lean Lab or while
packaging this entry or the Granville, van de Lune and te Riele 1989 entry of this repository.
No code from outside the lab is included, so the repository NOTICE does not change for this
entry. Binary Goldbach is open; nothing here claims it.

## What is proved, and on what range

Table 4 on page 2043 of the paper lists the 68 records of p of n, the least prime p such that
n - p is prime, for even n from 6 to 3325581707333960528. The entry checks the 28 rows with
n at most 10^8, from 6, 3 to 60119912, 1093, and nothing above 10^8. It is a finite check on
part of the paper's data.

* `LeanLab.OeSHP2014.table4_least`: for every row n, p of `table4` with n <= 10^8,
  `minGB n = p`, and every even m with 6 <= m < n has `minGB m < p`. So each printed row is
  exact and is a new record.
* `LeanLab.OeSHP2014.table4_complete`: every even m with 6 <= m <= 10^8 has a Goldbach
  partition, `minGB m` and `m - minGB m` are prime, and `minGB m` is at most the p of a row
  n, p with n <= m. So no record below 10^8 is missing from the table.

`table4` holds all 68 printed rows; the 40 rows above 10^8 are data only and are not checked.

## Changes made for this repository

* The lab proof used one bignum sieve equality over all integers per window of up to
  2 · 10^6, with `% 2 ^ W` and `Nat.log2`, in modules whose kernel memory grew with each
  window. Palomar's con-ron kernel is slow on that form. The entry uses the odd window checker
  of the Granville, van de Lune and te Riele entry instead: 125 windows of at most about
  990000 even numbers, four per module, each window inside one segment between two rows, so
  the bound tried in each window is the row value p of that segment.
* The lab's `table4_least` did not show that p of n equals the printed p at each row. The
  entry proves `minGB n = p` for each of the 28 rows, from the window bound at n and a divisor
  of n - x for every prime x < p, the certificates `cert_0` to `cert_27`.
* The lab's `table4_complete` stated only the bound on `minGB m`; since `minGB m` is 0 when m
  has no Goldbach partition, the entry also states that `minGB m` and `m - minGB m` are prime.
  The lab's leastness started at m = 4, where p of 4 = 2 is not a partition into odd primes;
  the entry starts at m = 6.
* Every file is in module syntax: the line `module`, then `public import`, the module doc
  comment and `@[expose] public section`.
* Not included: the lab's other results on this paper, among them Tables 5, 6, 7, 8, 9, 10, 11
  and 12, the cross table conditions, the maximal gap input and Theorem 2.1, and the paper's
  verification up to 4 · 10^18, which is cited in the lab and has no proof.
* The repository pins Lean and Mathlib v4.35.0-rc3, not the lab's v4.35.0, because Palomar's
  Challenge renderer fails on v4.35.0 and later, PalomarRegistry/PalomarSubmission issue 161.
* No file in the entry contains a placeholder proof, and no proof uses native code evaluation.

## Kernel cost

The window checks are evaluated by the kernel with `decide +kernel`. The range to 10^8 is
about 31 percent of the range of the Granville, van de Lune and te Riele entry, whose 339
windows con-ron with one worker accepted in 2187 seconds.

On a 2 core cloud sandbox with 8 GB of memory, on 2026-11-16, a `lake build` of the entry over
the prebuilt Mathlib cache took under two minutes, each window module 3 to 6 seconds, and the
Comparator run with the Lean kernel took 4.3 minutes and printed `Your solution is okay!`. On
the export of the Solution, con-ron v4.35.0-rc3 with `--verified` and one worker accepted 6211
declarations in 497 seconds.
